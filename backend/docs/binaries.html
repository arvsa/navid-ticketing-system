Command-line tools

The programs in src/bin: running the server, setting up accounts and trying the API from the terminal.

Basics

Run each tool from the project folder with cargo run --bin NAME. Flags for the tool go after --:

cargo run --bin login -- --email admin@north.demo.school

Every tool has --help, for example cargo run --bin users -- --help.

There are two kinds of tool:

  • Database tools (admin, users) talk to Postgres directly. They need only the database (docker compose up -d), not the server, and read DATABASE_URL from .env.
  • API tools (health, login, whoami, change_password, logout) call the running server (cargo run) like any client would. The ones that need a session share it through cookies.txt, which login writes and logout deletes. curl can use the same file: curl -b cookies.txt ....

Common flags of the API tools

FlagDefaultMeaning
--urlhttp://127.0.0.1:8080The server's address.
--cookie-filecookies.txtWhere the session is saved and read. Use different files to stay signed in as several people.
--originAPP_ORIGIN from .env, else http://localhost:5173Sent as the Origin header on changes; must match the server's APP_ORIGIN. Not used by health and whoami.

Server and database

backend database

The API server. It's the default binary, so plain cargo run starts it. It applies new database migrations on start and listens on BIND_ADDR (127.0.0.1:8080).

cargo run

It is configured only through .env; see REFERENCE.md for every setting.

admin database

Operator tasks that need no sign-in. They're recorded in the audit log as done by the system.

create-super-admin

Creates the first super admin (or another one) with a random temporary password, printed once. The account must choose its own password at first sign-in.

cargo run --bin admin -- create-super-admin --email you@school.org --first-name Ada --last-name Lovelace

reset-password

Gives any account a new temporary password (printed once), forces a change at the next sign-in, clears a lockout and signs the account out everywhere. Works for super admins too, including a locked-out one.

cargo run --bin admin -- reset-password --email jane@school.org

seed-demo

Fills an empty database with three branches, about 90 people and some issues. Every demo account's password is demo-password. It refuses to run if any branch exists.

cargo run --bin admin -- seed-demo

users database

Lists the accounts as a table: email, name, branches (with (admin) where they're an admin) and notes such as super admin, deactivated, locked or must change password. Read-only.

cargo run --bin users
cargo run --bin users -- --branch NORTH
cargo run --bin users -- --search jane
FlagMeaning
--branch CODEOnly current members of that branch.
--search TEXTOnly users whose email or name contains the text.

Passwords can't be shown: the database stores only argon2 hashes of them.

Through the API

These need the server running (cargo run) in another terminal.

health server

Checks GET /api/healthz and prints OK (server and database up), UNHEALTHY (server up, database not) or DOWN (server not reachable). The exit code is non-zero unless it's OK, so scripts can use it.

cargo run --bin health

login server

Signs in and saves the session to the cookie file. Without flags it signs in as the demo super admin.

cargo run --bin login
cargo run --bin login -- --email jane@school.org --password 'her-password'
FlagDefault
--emailsuperadmin@demo.school
--passworddemo-password

If the account has a temporary password, it says so: nothing but change_password, whoami and logout works until a new password is chosen.

A wrong email, wrong password, deactivated account and locked account all give the same "invalid email or password", on purpose. Five wrong passwords lock an account for 15 minutes.

whoami server

Shows who the saved session belongs to (name, email, super admin or not, branches and roles), or that you're signed out. Non-zero exit code when signed out.

cargo run --bin whoami

change_password server

Changes the password of whoever is signed in. Any user can run it for their own account, including right after signing in with a temporary password (use the temporary one as the current password). The session in the cookie file stays signed in; every other session of the account is signed out.

cargo run --bin change_password -- --current-password 'old-password' --new-password 'new-password'
FlagMeaning
--current-passwordRequired. The password you signed in with.
--new-passwordRequired. 8 to 128 characters.

See the password rotation tutorial for the full flow.

logout server

Ends the saved session on the server and deletes the cookie file. If the session had already expired it just deletes the file. If the server can't be reached, the file is kept so you can try again.

cargo run --bin logout

Passwords given as flags end up in your shell history. On a shared machine, put a space before the command (zsh and bash skip such lines when configured to) or clear the history afterwards.
