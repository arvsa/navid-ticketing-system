How passwords work here

  • Nobody, not even a super admin, can see a password. They're stored only as hashes.
  • To give someone a password, you create a temporary password. It's random, printed once, and you hand it over yourself (there's no email).
  • An account with a temporary password can sign in, but can do nothing else until it chooses its own password.
  • Choosing a new password always asks for the current one. Right after a reset, the current one is the temporary password.

Start the database before anything else, and the server for the steps that sign in:

docker compose up -d     # the database
cargo run                # the server, in its own terminal

1. First run: create the super admin

  1. Create the account operator · database only

    cargo run --bin admin -- create-super-admin --email you@school.org --first-name Ada --last-name Lovelace

    It prints Temporary password: …. Copy it now: it's shown only once.

  2. Sign in with the temporary password

    cargo run --bin login -- --email you@school.org --password 'TEMPORARY-PASSWORD'

    It notes that the account must change its password.

  3. Choose your own password

    cargo run --bin change_password -- --current-password 'TEMPORARY-PASSWORD' --new-password 'your-own-password'

    Password changed. You stay signed in and can use everything.

2. Rotate a user's password

For when someone forgot their password, was locked out, or their password should be replaced. You don't need their current password.

  1. Find the account operator · database only

    cargo run --bin users -- --search jane

  2. Give them a temporary password operator · database only

    cargo run --bin admin -- reset-password --email jane@school.org

    It prints the temporary password once. Their old password stops working, any lockout is cleared and they're signed out everywhere.

  3. Hand it over

    In person or another channel you trust. Don't post it in a shared chat.

  4. They sign in and choose their own the user

    cargo run --bin login -- --email jane@school.org --password 'TEMPORARY-PASSWORD'
cargo run --bin change_password -- --current-password 'TEMPORARY-PASSWORD' --new-password 'her-new-password'

    If you run these for them on your machine, finish with cargo run --bin logout so their session isn't left in your cookies.txt.

To confirm it worked, cargo run --bin users -- --search jane no longer shows must change password.

3. A user rotates their own password

When they know their current password, no admin is needed:

cargo run --bin login -- --email jane@school.org --password 'current-password'
cargo run --bin change_password -- --current-password 'current-password' --new-password 'new-password'

Their other sessions (other browsers or devices) are signed out; this one stays signed in.

4. Rotate the super admin's password

The same two ways work for the super admin:

SituationDo
You know the current passwordSection 3 with your own email.
Forgotten, locked out, or a scheduled rotationSection 2 with your own email: admin reset-password needs only the database, so it works even when no one can sign in.
cargo run --bin admin -- reset-password --email you@school.org
cargo run --bin login -- --email you@school.org --password 'TEMPORARY-PASSWORD'
cargo run --bin change_password -- --current-password 'TEMPORARY-PASSWORD' --new-password 'your-next-password'

Troubleshooting

MessageMeaning and fix
invalid_credentials at loginWrong email or password, or the account is locked (five wrong passwords lock it for 15 minutes) or deactivated. The message never says which. cargo run --bin users shows locked or deactivated; admin reset-password clears a lockout.
invalid_current_passwordThe --current-password is wrong. After a reset, it's the temporary password.
weak_passwordThe new password must be 8 to 128 characters.
password_change_requiredThe account still has a temporary password; run change_password.
Not signed incookies.txt is missing or the session ended (for example after a reset). Run login again.
origin_mismatchAPP_ORIGIN in .env differs from --origin. Run the tools from the project folder so they read the same .env.
Error: NotFound from reset-passwordNo account has that email. Check it with cargo run --bin users.

Passwords given as flags are saved in your shell history. On a shared machine, clear it afterwards (for example history -c in bash, or delete the lines from ~/.zsh_history).
