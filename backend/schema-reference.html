Enum types

Changing an enum needs a new migration (ALTER TYPE … ADD VALUE); values can't be removed easily.

issue_priority

lowmediumhighcritical

Used by issue.priority (default medium).

issue_state

openclosedcancelled

Used by issue.state. Check issue_closed_at: closed_at IS NULL exactly when state is open.

completion_mode

sharedper_member

Used by issue.completion_mode. shared: one work item per target, claimed by a member. per_member: one work item per member at send time.

target_kind

branchgroupuser

Used by issue_target.kind. Check issue_target_shape requires group_id/user_id to match the kind. branch only for super admin issues (enforced by check_issue_target). Targets are never deleted: removing one sets removed_at/removed_by (0004), and the partial unique index issue_target_once applies to active targets only, so a removed target can be added again.

permission_scope

owntargetedbranch

Used by group_permission.scope and permission.allowed_scopes (array).

rsvp_response

pendinggoingmaybedeclined

Used by event_rsvp.response. Check event_rsvp_responded: responded_at IS NULL exactly when pending.

work_status

openin_progressblockedpending_approvalapprovedcancelled
open → in_progress ⇄ blocked → pending_approval → approved
pending_approval → in_progress   (rejection)
any non-final    → cancelled

Used by work_item.status. Transitions are enforced in Rust; the DB enforces work_item_submitted (pending_approval/approved need submitted_at) and work_item_decided (approved needs decided_at).

Trigger functions

All plpgsql, RETURNS trigger. Errors raised here surface as SQLSTATE P0001 (raise_exception); map them to 409/422 in AppError.

set_updated_at()

BEFORE UPDATE. Sets NEW.updated_at := now(). Bound to 8 tables (see bindings).

reject_modification()

BEFORE UPDATE OR DELETE on audit_log. Always raises '<table> is append-only'.

create_default_group()

AFTER INSERT on branch. Creates the branch's All members group (is_default = true) and inserts 12 baseline group_permission rows:

issue.read        *       branch     issue.target      ticket  own
issue.create      ticket  branch     issue.target      event   own
issue.create      report  branch     work_item.update  *       targeted
issue.create      event   branch     work_item.assign  *       targeted
issue.edit        *       own        comment.create    *       branch
issue.close       *       own        member.view       *       branch

sync_default_group_membership()

AFTER INSERT OR UPDATE OF left_at on branch_membership. Joining (insert, or left_at → NULL) adds the user to the branch's default group (ON CONFLICT DO NOTHING). Leaving (left_at set) deletes all of the user's group_member rows in that branch.

check_group_member_active()

BEFORE INSERT on group_member. Raises if the membership has left_at set.

protect_default_group()

BEFORE UPDATE OR DELETE on user_group. Blocks deleting the default group and changing is_default.

check_group_permission()

BEFORE INSERT OR UPDATE on group_permission. Raises if scope isn't in the permission's allowed_scopes, or if issue_type_id is set on a permission with per_issue_type = false.

check_issue_target()

BEFORE INSERT OR UPDATE on issue_target. Raises if a branch-owned issue gets a target in another branch, or if a branch-kind target is added to an issue without requires_super_admin_approval.

Invariant functions (deferred constraint triggers)

These run DEFERRABLE INITIALLY DEFERRED, i.e. at COMMIT, so multi-statement changes (create branch + first admin, swap admins) pass. They do not prevent races between concurrent transactions: lock the branch row (SELECT … FOR UPDATE) before demoting admins.

assert_branch_has_admin(b uuid) RETURNS void

Helper. Raises 'branch % must have at least one active admin' if the branch is active and has no membership with is_admin, left_at IS NULL and an active user.

check_branch_has_admin()

On branch AFTER INSERT OR UPDATE OF is_active. Calls the helper with NEW.id.

check_membership_keeps_admin()

On branch_membership AFTER UPDATE OR DELETE. Calls the helper with OLD.branch_id.

check_user_deactivation_keeps_admins()

On app_user AFTER UPDATE OF is_active. Raises if deactivating leaves any active branch the user administers without an active admin.

check_super_admin_exists()

On app_user AFTER INSERT, UPDATE OF is_super_admin, is_active, or DELETE. Raises if users exist but no active super admin does. The bootstrap CLI must insert the first user as a super admin.

SQL functions

issue_visible(p_issue_id uuid, p_branch_id uuid, p_type_id smallint, p_is_private boolean, p_created_by uuid, f jsonb) RETURNS boolean

LANGUAGE sql STABLE. Created in 0002, replaced in 0004 and 0005; the description below is the 0005 version. The single read-visibility predicate for lists, dashboard and export. Must agree with authz::policy::can_read (tested).

WHERE issue_visible(i.id, i.branch_id, i.type_id, i.is_private, i.created_by, $1)

f is built by IssueFilter::for_actor(actor).into_json() in src/authz/filter.rs. Only branch-scope grants feed read and read_private:

{"me": "<uuid>", "super": false,
 "branches":     ["<branch>", ...],          -- current memberships
 "admin":        ["<branch>", ...],          -- admin in
 "read":         ["<branch>:<type|*>", ...],  -- issue.read @ branch
 "read_private": ["<branch>:<type|*>", ...],  -- issue.read_private
 "internal":     ["<branch>", ...]}          -- admin or comment.internal; not used by issue_visible

Returns true when any of these holds. Only active targets count (removed_at IS NULL).

PathCondition
Super adminf.super
Owncreated_by = me, and still a member of the issue's branch (or the issue is cross-branch)
User targetTargeted directly, and still a member of that target's branch
Group targetCurrent member of a targeted group (leaving a branch removes group membership via trigger)
Branch targetMember of a branch-kind target's branch
AssigneeAssignee of a work item on an active target, and still a member of the work item's branch
Branch accessIn the issue's branch (cross-branch: any active targeted branch): admin, or read_private, or read and the issue is not private. Grant keys are <branch>:<issue_type.code> or <branch>:*.

Consequence: leaving a branch ends all access to its issues, including ones you created or were assigned (0005).

Views

work_item_overview

work_item.* plus is_overdue boolean: sla_due_at < now() and status in open/in_progress/blocked; false when no SLA.

issue_overview

issue.* plus rollups over its work items: work_item_count, done_count (approved + cancelled), awaiting_approval_count, is_overdue, next_sla_due_at. Counts are bigint (i64 in Rust). Not permission-filtered: always combine with issue_visible.
